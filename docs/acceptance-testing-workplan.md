# Acceptance-Testing Workplan

The tasks that build the suite `docs/ACCEPTANCE_TESTING.md` describes, in the order
they unblock each other, and the first specs in full. When the suite runs and
`plans/acceptance-testing.md` closes, this file goes; the test plan stays.

## Tasks

### 1. Reset

`tests/e2e/pelilauta/reset-and-seed.ts` connects with the service principal,
reads the project id from it, and exits without touching anything when the id is
not the test project's. Behind that guard it recursively deletes the collections
on its list — `sites` alone, to begin with; recursion catches the `pages`
subcollections a batch delete leaves behind. A collection joins the list when a
spec writes to it, so a run never inherits what the one before created. The
script does not touch Auth: the example accounts' uids tie Auth to the Firestore
documents the seed writes, so the accounts persist between runs.

The script imports the application's own zod schemas
(`apps/pelilauta/src/schemas/`) to parse every document it writes, rather than
re-declaring their shape. Those files resolve their own imports the way Astro's
Vite build does, which plain Node does not, so a module-resolution hook,
`tests/e2e/pelilauta/schema-resolver-loader.mjs`, rewrites them first:

```
node --import tests/e2e/pelilauta/schema-resolver-loader.mjs \
  tests/e2e/pelilauta/reset-and-seed.ts
```

### 2. Accounts

The same script checks the three example accounts exist in Auth, and creates a
missing one:

- **existingUser** — a member with a profile; the actor of the first specs.
- **newUser** — an Auth account with no profile document, so the registration
  journey starts where a new reader does.
- **adminUser** — a member listed as an admin.

Credentials stay in the gitignored root `credentials.ts` the inherited suite
already reads. The script clears newUser's custom claims — the one Auth state a
run writes, and v18's seed cleared it for the same reason — so registration starts
clean.

### 3. Seed

The default test data, held as JSON under `tests/e2e/pelilauta/seed/`;
`docs/acceptance-testing-seed.md` lists the documents and their shape. Before it
writes the documents, the script uploads every file under `seed/assets/` to
Storage and resolves each document's `@asset:<filename>` placeholder to the
resulting download URL.

The three tasks above run as one script, but not yet as one command a spec run
starts on its own; wiring that in is the Harness task below.

### 4. Harness

A root Vitest project includes `tests/e2e/pelilauta/**/*.spec.ts` and runs it in a
single worker, because every spec shares one database. Its global setup runs reset
and seed, waits for the dev server, signs existingUser in through the login form
once, and saves the Playwright storage state every spec's browser context loads.
A root script runs the whole chain; `pnpm test` does not reach it
(`plans/debt/browser-tests-run-locally-only.md`).

### 5. Site creation specs

The three specs below, in `tests/e2e/pelilauta/sites/`.

## The first specs

Each spec drives `CreateSiteForm` as existingUser and asserts what a reader
observes. The form derives the site's URL key from the name on blur and checks its
availability, so each spec names its site uniquely per run.

### Create a site

1. Open the site creation page, name the site, and submit.
2. The browser lands on the new site's page, which shows the name and a front page.
3. The library listing shows the site.

### Create a hidden site

1. Open the options, switch **hidden** on, name the site, and submit.
2. The browser lands on the new site's page.
3. The public listing at `/sites` does not show the site. `/library` cannot
   carry the assertion: it lists what the reader owns, hidden or not.

### Create a site with autogenerated URLs

1. Open the options, switch **custom page keys** off; the address preview shows a
   generated key in place of one derived from the name.
2. Name the site and submit.
3. The browser lands on the new site's page, at an address whose key is not derived
   from the name.
