One sentence saying what it is and what it is for. A second only if the first
leaves a reader guessing where it is used.

## Example

Show it rendering, then the code that produced it — in that order, because the
reader is confirming they want it before they copy it.

<TheComponent someProp="value" />

```mdx
import TheComponent from '@design-system/books/…/TheComponent.astro'

<TheComponent someProp="value" />
```

## Props

| Prop | Type | Purpose |
| :--- | :--- | :--- |
| `someProp` | `string` | What it controls. Say "Required" here rather than in prose. |

## When to use it

- The case it is for, as an instruction rather than a description.
- The case it is for.

Do not use it when — name the alternative and link it, so a reader who came to
the wrong page leaves knowing where to go.

## Behaviour worth knowing

Only for behaviour that surprises: a build that fails, a silent fallback, a
prop combination that is rejected. Two or three sentences. Delete the section if
the component has none.

## Accessibility

The semantics it emits and what a consumer still owes — a label, a landmark, a
focus target. Delete if it renders nothing with semantics of its own.
