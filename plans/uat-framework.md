# UAT Framework

A plan coordinates an active epic. It is transient: it may carry behaviour while the
epic runs — behaviour that outlives the epic lands in a spec — and it may be deleted
after the epic closes. Its entries keep the goal and the remaining work legible, not
a delivery record.

## Goal

v21 gains an acceptance harness of its own: Vitest drives Playwright against a dev
server on the test Firebase project, and every run starts from one seeded state.
`docs/MIGRATION.md` rules the inherited v18 suite out as acceptance evidence; this
harness is what replaces it, proven by the site journeys as its first real cargo.

## Success criteria

- One command resets, seeds, and runs every spec under
  `tests/e2e/pelilauta/**/*.spec.ts` against the running application.
- The suite passes with existingUser creating a site, a hidden site, and a site
  with autogenerated URLs, asserting what a reader observes after each.
- `docs/ACCEPTANCE_TESTING.md` matches what runs.

## Guardrails

- The reset refuses every Firebase project except the test project.
- The three example accounts persist in Auth between runs.
- A spec asserts what a reader observes; it does not read Firestore to prove a
  write happened.

## Out of scope

- Retiring the inherited v18 suite; it goes when this suite covers it.
- CI wiring (`plans/debt/browser-tests-run-locally-only.md`).
- Emulator support; the suite runs on the test project.
- Journeys for newUser and adminUser beyond their seeded accounts.

## Possible work (non-binding)

- **Site creation specs** — the autogenerated-URL journey;
  `docs/acceptance-testing-workplan.md` carries the steps and assertions.

## Done

- Test plan: `docs/ACCEPTANCE_TESTING.md` and the workplan are written and
  accepted.
- Seed: inventory in `docs/acceptance-testing-seed.md`, JSON and assets under
  `tests/e2e/pelilauta/seed/`.
- Reset and seed: `tests/e2e/pelilauta/reset-and-seed.ts` wipes the named
  collections, checks the example accounts, uploads the seed assets, and writes
  the seed through the application's schemas. Run once against `skaldbase-test`
  and verified.
- Harness: the root Vitest project, `pnpm test:uat`, runs reset and seed, brings
  up the dev server or reuses one, signs existingUser in, and hands each spec a
  signed-in page from `tests/e2e/pelilauta/harness.ts`.
- Create a site: the first journey passes.
- Create a hidden site: the journey passes, against the public listing at
  `/sites` rather than `/library`, which lists what the reader owns whether it
  is hidden or not.

## Open questions

- None open. The harness signs in through the login form: a minted session
  changes authentication on a surface v21 shares with live v18, which
  `plans/debt/e2e-signs-in-through-the-form.md` holds for its own epic.
