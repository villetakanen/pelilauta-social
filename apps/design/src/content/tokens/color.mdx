Declared color custom properties and values, read from their writable JSON sources —
`tokens/themes/default.json`, `tokens/semantic-color.json`, `tokens/elevation.json`,
and `tokens/transparency.json`. `scripts/generate-tokens.mjs` renders the same sources
to `styles/chroma.css`, `styles/semantic.css`, `styles/elevation.css`, and
`styles/transparency.css`, which the application imports. Color selection and contrast
rules are defined in [Colour System](/principles/color-system). Swatches resolve
dynamically in the active color scheme.

## Semantic roles

Component-facing color tokens, declared in `tokens/semantic-color.json`. Each role
defines light and dark values in a single `light-dark()` declaration.

## Elevation shadows

Elevation shadow tokens declared in `tokens/elevation.json`. Shadow geometry scales
with `--cn-grid` as defined in [Units and grid](/tokens/units).

## Transparency ladder

The shares a translucent layer may take, declared in `tokens/transparency.json`. A
rung carries no colour and no scheme arm; the layer mixing it supplies both. See
[Colour System](/principles/color-system) for the ladder as a specimen, and
[Surface reference](/base/surface) for the levels that cede to a poster.

<DsTokenTable source={roleDeclarations(transparency)} caption="Transparency ladder" />

## Reference palette

Primitive OKLCH color scales, declared in `tokens/themes/default.json`. UI components
consume semantic roles rather than referencing primitive palette tokens directly; the
exceptions are documented decorative uses, stated in each component's specification.
