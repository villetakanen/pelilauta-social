Declared color custom properties and values, read from their writable JSON sources —
`tokens/themes/default.json`, `tokens/semantic-color.json`, and
`tokens/elevation.json`. `scripts/generate-tokens.mjs` renders the same sources to
`styles/chroma.css`, `styles/semantic.css`, and `styles/elevation.css`, which the
application imports. Color selection and contrast rules are defined in
[Colour System](/principles/color-system). Swatches resolve dynamically in the active
color scheme.

## Semantic roles

Component-facing color tokens, declared in `tokens/semantic-color.json`. Each role
defines light and dark values in a single `light-dark()` declaration.

## Elevation shadows

Elevation shadow tokens declared in `tokens/elevation.json`. Shadow geometry scales
with `--cn-grid` as defined in [Units and grid](/tokens/units).

## Reference palette

Primitive OKLCH color scales, declared in `tokens/themes/default.json`. UI components
consume semantic roles rather than referencing primitive palette tokens directly; the
exceptions are documented decorative uses, stated in each component's specification.

## Cyan 4 aliases

`styles/compat/cyan-4.css` maps legacy names onto these roles until the surfaces still
running on Cyan are replaced. It is removed before `v21.0.0-rc.1` and nothing new reads it.
`docs/MIGRATION.md` owns the sweep.
