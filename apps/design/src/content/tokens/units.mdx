This is the lexicon: what the tokens are, and what each one is worth. How these
measurements recur in components, and how radii relate to the grid, is documented
in the [Spatial System](/principles/spatial-system) book.

Every table below is read from `styles/units.css` when this page is built, so it cannot
list a token that does not exist or miss one that does.

## Control geometry

A button's visible pill and the row it occupies, both grid multiples. The pill is narrower
than the row so a control centres on the grid without the row growing around it; the
button stylesheet reads both and derives its radius from the first.

  source={unitsSource}
  prefix="--cn-button"
/>

## Icon sizes

Absolute `rem` literals rather than grid multiples, following v20, which files them beside
the grid and marks them "absolute, not grid-derived". They scale with the reader like
every other `rem` length; they simply do not derive from `--cn-grid`. Four of the five land
on the grid anyway — the medium default is four and a half steps, which is the reason the
family is stated absolutely.

They are declared in `styles/units.css` beside the grid: two token files of a dozen lines
each bought nothing, so the primitives that are not colour share one stylesheet.

## Breakpoints

Stated in `rem`, so a threshold follows a reader who enlarges their default text; the
behaviour is documented under "Browser Font Settings" in the
[Spatial System](/principles/spatial-system) book.
A media or container query can't read a custom property, so a rule that needs the
threshold states the literal — the typography downshift does this — and a test pins
the literal to the token declared here.

## Elevation shadows

The four elevation shadows are declared in `styles/color-theme.css`, not here, but they
are grid multiples and depend on `--cn-grid`. `styles/tokens.css` composes both families,
and it is that dependency this page exists to make visible; their declaration order does
not affect custom-property resolution.

Their values are in the [Colour](/tokens/color) lexicon, which is where the stylesheet
that declares them is published. `packages/design-system/test/units.test.ts` asserts that
the token entry point composes both families, rather than testing a rendered shadow
against a page that happened to import them.
