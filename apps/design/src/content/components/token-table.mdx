A **specimen** is a component a book imports for the part that must read real source. It
exists so that a page cannot state a value the design system does not ship: anything a
writer would otherwise copy by hand — a token's value, a rule in a stylesheet — goes
through one instead.

`TokenTable` is the specimen for token lexicons. Give it a stylesheet and it renders every
declaration in it, in the stylesheet's own order.

## The guarantee is completeness, not correctness

A lexicon's job is to be exhaustive, and the failure it must not have is a quiet one. A
table missing a row looks exactly like a table, so `TokenTable` reads the stylesheet at
build time and lists what it finds there — it cannot omit a token that exists, and it
cannot invent one that does not.

What it does **not** verify is whether those values are right. Parity with Cyan 4, the
grid derivation, and whether the elevation shadows can resolve are asserted in
`packages/design-system/test/units.test.ts`, against the stylesheets themselves. A book
that renders is not a book that is correct.

## A filter that matches nothing fails the build

The dangerous case is a rename. If a filtered table stops matching, the honest outcomes
are an empty table or every token in the file, and both are pages that lie without
saying so. `TokenTable` throws instead, naming the filter that missed, so the build fails
where the mistake is.

This is the one behaviour worth knowing before using it: a book that asks for a token is
asserting the token exists.

## Using it

Import the stylesheet with `?raw` and pass it as `source`. Select rows with `names` for
an exact set, or `prefix` for a family.

| Prop | Purpose |
| :--- | :--- |
| `source` | The stylesheet text. Required. |
| `names` | Exact token names to show. |
| `prefix` | Show every token whose name starts with this. |
| `caption` | Names what the reader is looking at. |
| `noteLabel` | Heading for the trailing-comment column. Defaults to "Resolves to". |

A declaration's trailing inline comment becomes its last column, which is how the resolved
length reaches the reader beside the formula that produces it. A comment on its own line
introduces what follows and is left alone.

## It renders itself

This page's own table, produced from `styles/units.css` by the component it documents:

<TokenTable
  source={unitsSource}
  names={['--cn-grid', '--cn-gap', '--cn-line']}
  caption="The spacing tokens, as this specimen reads them"
/>

## What this does not cover

`TokenTable` is a build-time specimen and runs no client script, so it has no behaviour a
browser would reveal — its tests are in `packages/design-system/test/token-table.test.ts`
and need no browser. Computed values, which do need one, are outside it: no specimen here
reports what a `var()` chain resolves to on screen.

The full token vocabulary is in the [Units and grid](/tokens/units) and
[Colour](/tokens/color) lexicons.
