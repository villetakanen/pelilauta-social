`Icon` renders a single inline SVG vector glyph resolved from a semantic noun. Artwork
inherits the surrounding text colour via `currentColor` for monochrome icons, while branded
marks preserve source-encoded palette values.

## When to use it

- Visual reinforcement in buttons, navigation rails, list rows, and card headers.
- Visual indexing of content categories and domain entities.

Do not use `Icon` for user profile pictures; use [CnAvatar](/components/cn-avatar).
Icon selection guidelines and catalogue vocabulary are documented in
[Iconography principles](/principles/iconography).

## Example

<Icon noun="fox" />

```svelte
<script>
  import Icon from '@design-system/components/Icon.svelte'
</script>

<Icon noun="fox" />
```

## Variants and states

`Icon` provides five size steps, contextual theme colouring, and tiered resolution fallbacks.

### Sizes

Five dimension steps declared in `rem` to scale proportionally with browser font preferences:

<IconSizes
  source={iconSource}
  usage={{
    xsmall: 'Inline help and status markers',
    small: 'Buttons and list rows',
    medium: 'Navigation and default controls',
    large: 'Feature headers and card banners',
    xlarge: 'Empty states and hero callouts',
  }}
/>

### Colour and inheritance

Monochrome icons inherit `currentColor` across themes. Setting `color` on the parent container
automatically recolours the icon.

<IconContext
  source={themeSource}
  names={['--cn-text', '--cn-text-low', '--cn-link', '--cn-color-error']}
  caption="One noun across four semantic colour roles in Light and Dark"
/>

### Source resolution tiers

Nouns resolve sequentially across four tiers: open-source catalogue, managed proprietary submodule,
bundled essential fallbacks, and the missing glyph fallback.

    menu: 'Bundled essential fallback icon',
    'no-such-noun': 'Missing glyph fallback for unlisted noun',
  }}
  caption="Source tier resolution behaviour"
/>

## Composition

`Icon` renders as an `inline-flex` container with `aspect-ratio: 1 / 1`. Spacing between
an icon and adjacent text labels is managed by parent containers via CSS `gap`.

## Reference

### Props

| Prop | Type | Default | Purpose |
| :--- | :--- | :--- | :--- |
| `noun` | `string` | `''` | Semantic icon noun. Empty or unlisted nouns render the missing glyph. |
| `size` | `'xsmall' \| 'small' \| 'medium' \| 'large' \| 'xlarge'` | `'medium'` | Sizing step. |
| `aria-label` | `string` | `''` | Accessible name override. Defaults to `noun`. |
| `decorative` | `boolean` | `false` | Hides the icon from assistive technology and suppresses browser tooltips. |

### Tokens

Icon dimensions are declared in `styles/units.css` (`--cn-icon-size-*`). The component
declares no colour tokens, inheriting foreground colour via `currentColor`.

## Accessibility

- By default, `Icon` emits `role="img"`, sets `aria-label={noun}`, and includes an SVG `<title>` tooltip.
- Pass `aria-label` to provide localized or context-specific descriptions (such as brand names).
- Set `decorative={true}` when an adjacent text label already conveys meaning, or when the icon is inside an icon-only button that declares its own `aria-label`.

## Not shown here

**Proprietary tier resolution.** Proprietary licensed icons resolve via the optional
`@myrrys/proprietary` submodule. In environments where the submodule is omitted, proprietary
nouns resolve to the missing glyph.
