`CnPoster` replaces the document ground plane with an attenuated background image.
A multi-stop gradient wash overlays the image. Legibility comes from which surface
levels cede to the artwork and how far; see [Under a poster](/base/surface#under-a-poster).

## When to use it

- Landing pages, community hubs, or profile headers featuring hero artwork.
- Maximum one poster instance per page.

Use standard [Surface](/base/surface) containers for prose and dense data. `CnPoster`
renders statically and does not provide image error fallbacks.

## Example

```astro
---
import CnPoster from '@design-system/components/CnPoster.astro'
---

<Page>
  <CnPoster
    slot="app-background-poster"
    src="/sites/aamunkoin-vartijat/poster.webp"
    md="/sites/aamunkoin-vartijat/poster-wide.webp"
  />
</Page>
```

## Variants and states

`CnPoster` supports scrolling and pinned viewport placements, adaptive theme tinting, and media query suppression.

### Placement modes

- **Scrolling (default):** Covers the initial viewport height and dissolves smoothly into the page ground plane at its lower edge.
- **Pinned (`pinned={true}`):** Fixes the poster relative to the viewport; content scrolls continuously over the background layer.

### Theme tint and blending

The artwork renders at 72% opacity under theme-specific colour overlay washes:

| Theme | Overlay Tints | Blend Mode | Strength |
| :--- | :--- | :--- | :--- |
| Light | Surface 90, Primary 40 / 80 | `overlay` | 100% |
| Dark | Primary 10 to 80 | `hard-light` | 44% |

### Viewport and media query suppression

The poster layer is automatically suppressed (rendering pure background surfaces) under:
- Viewport widths below 620px (`@media screen and (min-width: 38.75rem)` guards the
  stage; below it the poster never renders).
- Print. The same guard names `screen`, which print is not, so the stage never applies
  on paper and every cession inside it is inactive.
- `prefers-reduced-transparency: reduce`.
- `forced-colors: active`.

## Composition

Mount `CnPoster` in the `app-background-poster` slot as a direct child of `<body>`.

When an element with `id="cn-poster"` exists in the DOM, surrounding application chrome
adapts transparency:

| Surface Selector | Applied Treatment |
| :--- | :--- |
| `--cn-app-bar-background-sticky` | `transparent` |
| `nav#rail`, `nav#tray` | `transparent` |
| `.elevation-0` | cedes a wide share of the [transparency ladder](/tokens/color) (`--cn-transparency-6`) |
| `.elevation-1`, `.elevation-2` | cede a narrow share (`--cn-transparency-2`) |
| `.elevation-3`, `.elevation-4` | unmodified, opaque |

The shares are ladder rungs rather than raw percentages, so the table names the
token; see [Under a poster](/base/surface#under-a-poster).

## Reference

### Props

| Prop | Type | Purpose |
| :--- | :--- | :--- |
| `src` | `string` | Required artwork image URL (default and mobile viewports). |
| `md` | `string` | High-resolution candidate URL loaded on viewports >= 960px. |
| `pinned` | `boolean` | Fixes poster to the viewport. Defaults to `false`. |

### Tokens

`CnPoster` declares no custom properties. It reads colour ramps from [Colour](/tokens/color),
ground plane tokens from `--cn-color-surface`, and overrides `--cn-app-bar-background-sticky` on `body`.

## Accessibility

`CnPoster` renders an `<img>` with an empty `alt=""` attribute and is omitted from the
accessibility tree. It disables pointer events (`pointer-events: none`) and carries no
tab stops.

## Not shown here

**Application chrome surface attenuation.** Chrome adaptation rules for `nav#rail` and
`nav#tray` are declared in `styles/poster.css`.

**High-contrast and reduced-transparency emulation.** Verified in emulated browser environments
via automated media query tests.
