`CnCard` presents an independently meaningful content entity (such as a discussion thread,
library article, or game system). It requires a `title` and supports optional cover images,
contextual noun icons, supporting descriptions, body slots, and trailing action bars.

## When to use it

- Entity previews in collections, search results, feeds, and directory listings.
- Content summaries requiring independent secondary controls alongside a primary destination.

Do not use `CnCard` for untitled panels, modal dialogs, or transient banners; use base
[Surface](/base/surface) containers instead. Containing layout grids control card width and gutter spacing.

## Variants and states

`CnCard` provides four configurable axes: destination linking, elevation tiers with attention flags, cover artwork with fallback handling, and container-query responsiveness.

### Destinations and links

When `href` is provided, the card remains passive while the `title` and cover image become
primary keyboard and pointer navigation targets. Secondary links and buttons within the
eyebrow, body, or actions slot remain independently operable.

</Composition>

### Elevation and attention indicators

`CnCard` supports standard surface elevation levels (0 through 4). Attention flags indicate
notification or alert states:

- At elevation 0, a 1px border is applied (`var(--cn-border)`).
- Elevation 4 applies high-contrast foreground text on primary background surfaces.
- Attention flags (`notify`, `alert`) display visual corner indicators.

<Composition themes caption="Elevation tiers (0–4) and attention indicator states">

#### Dynamic client-side flag toggling

In server-rendered listings, attention flags can be updated dynamically via DOM class toggles
without requiring full component re-rendering:

```ts
const card = document.querySelector('#thread-card-abc123 .cn-card')
card?.classList.toggle('has-notify', hasUnreadMessages)
```

The classes `.cn-card`, `.has-notify`, and `.has-alert` form part of the public styling contract.

### Visual identity and cover fallbacks

A semantic `noun` renders beside the title in text cards, or in the upper-right corner of cover images.
Cover images render with a 16:9 aspect ratio and an overlaid primary tint gradient.

When a cover image fails to load or resolves to an invalid URL, the card automatically displays
the SVG fallback artwork beneath the transparent image box without requiring client-side error handlers.

<Composition themes caption="Noun icon, loaded cover, missing cover fallback, and linked cover">

</Composition>

### Container query behaviour

`CnCard` declares `container-type: inline-size`. The heading title retains `h4` typography metrics
across container widths and clamps to a maximum of 2 rendered lines with ellipsis truncation.

</Composition>

## Composition

`CnCard` organizes content across four vertical regions:
1. **Cover & Eyebrow:** 16:9 hero image and uppercase metadata label.
2. **Title:** Clamped `h4` heading with optional icon.
3. **Body:** Secondary description paragraph and arbitrary child slot elements.
4. **Actions:** Fixed-height bottom bar (7x grid) for action buttons and metadata.

## Reference

### Props

| Prop | Type | Default | Purpose |
| :--- | :--- | :--- | :--- |
| `title` | `string` | — | Required card heading text. |
| `description` | `string` | `''` | Secondary description text rendered below the heading. |
| `elevation` | `0 \| 1 \| 2 \| 3 \| 4` | `1` | Surface elevation level. |
| `href` | `string` | `''` | Navigation destination linking title and cover image. |
| `cover` | `string` | `''` | Cover image URL. |
| `srcset` | `string` | `''` | Responsive image `srcset` candidates. |
| `sizes` | `string` | `''` | Responsive image `sizes` query. |
| `noun` | `string` | `''` | Semantic icon noun. |
| `notify` | `boolean` | `false` | Displays informational attention flag. |
| `alert` | `boolean` | `false` | Displays warning attention flag. |
| `eyebrow` | `Snippet` | — | Content rendered above the title. |
| `children` | `Snippet` | — | Supplementary body content. |
| `actions` | `Snippet` | — | Trailing action bar content. |

### Tokens

`CnCard` consumes surface elevation tokens from [Colour & Surface](/principles/color-system)
and typography tokens from [Typography](/tokens/typography). It supports an optional
`--cn-border-radius-card` override (defaulting to `--cn-border-radius-large` / 16px).

## Accessibility

`CnCard` renders as a semantic `<article>` element containing an `<h4>` heading. Cover images
and placeholder artwork emit `aria-hidden="true"` and empty `alt=""` attributes. All critical
entity information must be conveyed through card text.

## Not shown here

**Loading card state.** `CnCard` requires an existing title and does not provide an internal
loading skeleton. Loading states must render `CnLoader` within the parent layout container.
