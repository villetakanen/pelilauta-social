Pelilauta is a text-rich site — threads, character sheets, the shared library. An icon
here does a job: it makes a row scannable, it marks a recurring action, it anchors a
control. Read this to decide whether the thing you're building takes an icon at all, and
which one. [Icon](/components/icon) explains how a single icon renders.

## An icon that doesn't aid understanding goes

Add one where it speeds recognition of something the reader already knows, or where it
anchors an interaction they'll repeat. If it makes the element ambiguous, drop it.

Give one meaning one noun, everywhere it appears. A reader who has learned `label-tag` on
a thread should recognise it in the library.

## Reserve icon-only controls for actions everyone knows

Close, search, menu, settings. Everything domain-specific — publish a site, archive a
thread, roll a die — carries visible text beside its icon.

An icon-only control still needs an accessible name, and that name states the action it
performs — "Close" for a control carrying a cross. The control owns that name; the icon
doesn't supply it.

## Never let colour or an icon carry a state alone

A state reaches the reader as text or a structural change. An icon or a colour reinforces
it. A row that says "error" only by turning an icon red says nothing to a reader who
can't see it, and little to one skimming.

## One group, one size

A list, a navigation rail, a row of buttons: pick a size for the context and hold every
icon in it to that size. Sizes come from the tokens, never from a hand-written length.
[Icon](/components/icon) lists them and says which is which.

An icon beside text aligns to that text. The layout around it owns that alignment.

## Do and don't

| Do | Don't |
| :--- | :--- |
| Pair an unfamiliar or domain icon with a visible label | Ship an ambiguous icon alone |
| Keep one size within a list or navigation group | Mix sizes, or drop in an inline SVG |
| Give an interactive icon a target big enough to hit | Attach an action to a bare glyph with no padding |
| Signal state with text or shape, and reinforce with the icon | Signal state with colour alone |

## Choose by meaning, from what exists

Every icon is a noun that describes meaning — `search`, `fox` — so artwork can be redrawn
without renaming it. Pick from the catalogue below by the purpose you're serving. A noun
outside it renders the missing glyph.

Nouns marked proprietary come from the managed tier: licensed artwork the project doesn't
own, available only where that submodule is.

## Adding a noun is a decision, not a step

The catalogue grows one icon at a time, alongside the surface that needs it. Admitting
open-source artwork means recording its source and licence in the tier's `PROVENANCE.md`,
and a human approving it. Artwork the project can't license lives in the managed submodule
and never in this repository.

A migration doesn't rename a noun or re-point it at different artwork. Both are catalogue
decisions of their own.
