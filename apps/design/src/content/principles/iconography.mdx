Icons accelerate scanning, reinforce recurring interactions, and anchor primary UI
controls. Every icon is identified by a semantic noun describing its meaning rather
than its visual appearance.

For component invocation details and source resolution tiers, see [CnIcon component](/components/cn-icon).

## Purpose and recognition

Icons are visual aids rather than primary content:
- Use icons to accelerate recognition of established actions or concepts.
- Omit icons where they add visual clutter or ambiguity.
- Maintain consistent noun assignments across all applications (for example, `label-tag` represents tags in discussion threads and library entries alike).

## Icon-only controls

Reserve icon-only controls for universal interface conventions: `close`, `search`,
`menu`, and `settings`.

All domain-specific actions (such as archiving threads, publishing articles, or rolling
dice) require a visible text label beside the icon. Every icon-only control carries an
accessible name of its own, and the icon inside it is decorative — an icon that announces
its noun becomes part of the name the control is announced by.

## Reinforcing state

A state is available programmatically, never only in view. Colour, an icon or a shape
carries it for a reader scanning the page; the element itself carries it for assistive
technology — `aria-current` on the destination a reader is at, for example, rather than
the indicator painted behind it.

## Sizing and visual consistency

UI regions must maintain uniform icon sizing across sibling controls. In lists, navigation
rails, and button groups, all icons share a single tokenized size step.

## Usage guidelines

| Do | Don't |
| :--- | :--- |
| Pair unfamiliar or domain-specific icons with visible text labels | Display ambiguous icons without text labels |
| Maintain a single icon size within a list or navigation bar | Mix icon sizes within a single control group |
| Declare state on the element and paint it with icon or colour | Paint state without declaring it on the element |

## Icon catalogue by semantic domain

Icons are grouped by semantic domain. Any noun requested outside this vocabulary renders
the fallback missing glyph.

A noun is stable: artwork behind it may be redrawn, but the noun is not renamed or
re-pointed at different artwork, so a noun stored in data keeps meaning what it meant.
