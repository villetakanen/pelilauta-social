Surface provides the standard container for bounded content and five utilities for
expressing elevation. Applications receive both from
`@design-system/styles/ds.css`.

Use `.surface` when content needs the system inset and a local query context. Use
an elevation utility on its own when an existing component needs only the visual
level.

## The container

`.surface` applies the standard content inset and establishes the `surface-area`
query container. Components inside it can therefore respond to the width available
inside the surface, independently of the viewport. Its default visual treatment is
elevation 1.

| Declaration | Value                        |
| :---------- | :--------------------------- |
| `padding`   | `--cn-gap`                   |
| `container` | `surface-area / inline-size` |
| Level       | 1                            |

The inset remains `--cn-gap` at every width. A composition requiring another inset
must state that exception where it is used.

## The levels

Each elevation utility applies the background and shadow assigned to one level.
Choose the level by the role of the element in the composition; the
[Colour & Surface principles](/principles/color-system) define that hierarchy.

| Class          | Background       | Shadow                    | Use for                                        |
| :------------- | :--------------- | :------------------------ | :--------------------------------------------- |
| `.elevation-0` | `--cn-surface`   | none                      | The application ground plane                   |
| `.elevation-1` | `--cn-surface-1` | none                      | Resting content: cards and panels              |
| `.elevation-2` | `--cn-surface-2` | `--cn-shadow-elevation-2` | Content raised above a resting surface         |
| `.elevation-3` | `--cn-surface-3` | `--cn-shadow-elevation-3` | Floating or active content: menus and popovers |
| `.elevation-4` | `--cn-surface-4` | `--cn-shadow-elevation-4` | The highest system layer: dialogs              |

Elevation 0 paints an opaque ground plane using surface step 95 in Light and step
20 in Dark. Elevations 0 and 1 are shadowless. Elevations 2 to 4 apply progressively
larger shadows when they render without an elevated ancestor.

The Light and Dark themes do not derive depth from colour in the same way. Levels
1 to 3 share one background in Light, while Dark separates levels 2 and 3 by
lightness. Level 4 leaves the surface family: it uses primary step 99 in Light and
step 40 in Dark.

Every level carries the inherited body foreground at WCAG 2.2 AA, so an element
with an elevation class and no colour of its own is readable. Raise a foreground to
strengthen it, not to rescue it. Level 4 is the exception worth naming: the
de-emphasised roles are unreadable on it in Dark, so metadata and links inside a
system-layer surface take a stronger role.

## Overriding a surface's level

Add one elevation class to `.surface` to select another visual level. Padding and
containment remain unchanged.

```html
<div class="surface elevation-3">A menu panel</div>
```

  caption="A surface at its default level and with an explicit elevation"
>

## Nesting

Nested elevation is relative to the nearest elevated ancestor. The child keeps the
background assigned to its own level; its visible shadow represents only the
difference between the two levels. Levels in a nested chain increase from ancestor
to descendant.

| Ancestor | Child | Visible shadow            |
| :------- | :---- | :------------------------ |
| 1        | 2     | none                      |
| 1        | 3     | `--cn-shadow-elevation-2` |
| 1        | 4     | `--cn-shadow-elevation-3` |
| 2        | 3     | none                      |
| 2        | 4     | `--cn-shadow-elevation-2` |
| 3        | 4     | none                      |

A rise of one level is always shadowless. Larger rises use the shadow corresponding
to the distance from the nearest ancestor, preventing nested shadows from
accumulating.

<Composition
  themes
  caption="Elevation 4 relative to ancestors at elevations 1 and 3"
>
  <div class="surface elevation-1">
    Ancestor at elevation 1
    <div class="surface elevation-4">Child at elevation 4</div>
  </div>
  <div class="surface elevation-3">
    Ancestor at elevation 3
    <div class="surface elevation-4">Child at elevation 4</div>
  </div>
</Composition>

`.surface` participates in this calculation at elevation 1 by default. When it also
has an elevation class, the selected level is used.

## Attention states

`has-notify` and `has-alert` paint a triangular flag in the upper-right corner of any
element. Notification uses the information role, alert the warning role, and alert
wins when both are set. The flag inherits its host's corner radius and takes no
pointer events.

```html
<div class="surface has-notify">A row with unread content</div>
```

<Composition themes caption="A surface with each attention state">
  <div class="surface has-notify">Notification</div>
  <div class="surface has-alert">Alert</div>
</Composition>

The states are here rather than inside a component because a card and a listing row
are the same signal on different containers: [CnCard](/components/cn-card) composes
these same classes and adds only the inset that pulls the flag over its border.

They are safe to toggle from the client on an element that is never hydrated — the
rules read the classes and nothing else:

```ts
row.classList.toggle('has-notify', unread)
```

The flag announces nothing. A consumer that shows one carries the meaning in text or
another accessible state.
