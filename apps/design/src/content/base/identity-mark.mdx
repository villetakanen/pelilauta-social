Identity marks represent user and system profiles. We provide two formats: the pictorial
mark (`CnAvatar`) and the textual mark (`.cn-nick`). `CnAvatar` renders statically on the
server with pure CSS fallback layering.

## Pictorial mark states and sizes

`CnAvatar` renders an image avatar, initials fallback, or anonymous glyph:

1. **Image:** Profile picture clipped to a circle.
2. **Initials:** First two characters of `nick` over a deterministic backdrop color derived from the nickname string.
3. **Anonymous:** Default `avatar` icon on `--cn-color-surface-2` when no nickname is provided.

Initials render beneath the image in DOM order, providing a scriptless fallback if image
loading fails.

<Composition themes caption="Image, initials, anonymous glyph, and failed image fallback">
  <IdentitySpecimens group="states" />
</Composition>

| State | Visual | Backdrop |
| :--- | :--- | :--- |
| Image | Profile picture cropped to circle | Covered by image |
| Initials | Two characters of `nick` | Derived from `nick` |
| Anonymous | `avatar` icon | `--cn-color-surface-2` |

The component supports three standard sizes aligned to layout line multiples:
- **Small (1.5 lines / 36px):** Inline beside body text.
- **Medium (2 lines / 48px, default):** Section headers and feed items.
- **Large (3 lines / 72px):** Profile pages and dedicated account views.

## Dynamic backdrops and contrast

Initials backdrops are derived from the nick, between `--_avatar-backdrop-from` and
`--_avatar-backdrop-to`, to separate the profiles that share a view. The derivation is an
implementation detail and the colour is not promised: both ends are token roles, so a
palette revision recolours every avatar. A consumer needing a stable colour stores one.

These two tokens, and the `--_on-avatar` text role they are read against, are private to
`CnAvatar`: no other capability paints a derived backdrop, so they carry no `--cn-*` name
and are declared on the mark itself rather than on `:root`
(`docs/ARCHITECTURE.md`). They still draw from the same public `--chroma-*` roles a
palette revision changes.

<Composition themes caption="Six distinct nicknames and resulting derived backdrops">
  <IdentitySpecimens group="distinct" />
</Composition>

All derived backdrop values maintain WCAG AA contrast:
- 4.5:1 against `--_on-avatar` for the initials.
- 3:1 against the page surface behind the mark.

## Avatar lists

Use `.cn-avatar-list` (typically on `<ul>`) to group multiple identity marks.

<Composition themes caption="Linked avatars in an avatar list">
  <IdentitySpecimens group="list" />
</Composition>

List avatars overlap horizontally. To preserve visual separation without depending on
external surface backgrounds, avatars within a list inset their image, revealing a
perimeter rim of the derived backdrop color.

All avatars in a single list should use the same size modifier.

<Composition themes caption="Avatar lists in small and medium sizes">
  <IdentitySpecimens group="list-sizes" />
</Composition>

When list content exceeds container width, the list wraps with aligned leading edges.

### Overflow count

To indicate additional profiles, append `<span class="cn-avatar-list__overflow">`
containing a plus prefix and count. The overflow badge uses anonymous mark styling and
must match the list size modifier.

<Composition themes caption="Avatar list with overflow counter">
  <IdentitySpecimens group="list-overflow" />
</Composition>

Marks with no nick derive no backdrop, so a run of them separates only by elevation.

<Composition themes caption="An anonymous run: no nicks, no derived backdrops">
  <IdentitySpecimens group="list-anonymous" />
</Composition>

```mdx
<ul class="cn-avatar-list">
  {shown.map((profile) => (
    <li>
      <a href={`/profiles/${profile.key}`} aria-label={profile.nick}>
        <CnAvatar src={profile.avatarURL} nick={profile.nick} aria-hidden />
      </a>
    </li>
  ))}
  <li><span class="cn-avatar-list__overflow" aria-hidden="true">+{rest}</span></li>
</ul>
```

## Interactive states

Identity marks are non-interactive by default. When wrapped in an `<a>` anchor:
- The circular avatar suppresses default text underlines, lifts to elevation 2 on hover, and applies a circular keyboard focus ring.
- The textual nick (`.cn-nick`) keeps its resting colour and applies `--cn-color-link-hover` and `--cn-color-link-active`.

## Accessibility

`CnAvatar` announces `nick` as its accessible name.

When an avatar is paired with visible text naming the profile (such as `.cn-nick` or a
text link), pass `aria-hidden="true"` to `CnAvatar` to prevent duplicate screen reader
announcements. The anonymous mark without a `nick` is hidden from assistive technology
by default.
