An identity mark stands for one profile. There are two: the pictorial mark, the
`CnAvatar` component, and the textual mark, the `.cn-nick` class. Both arrive with
the design system's stylesheet, and `CnAvatar` renders on the server without
hydrating.

  <IdentitySpecimens group="nick" />
</Composition>

## What the pictorial mark shows

The mark shows the profile's image. Where no image renders, it shows the first two
characters of the nick over a backdrop derived from that nick. Where there is no
nick either, it shows the generic glyph on `--cn-surface-2`: with no nick there is
nothing to derive a backdrop from.

The fallback is layered, not scripted. The initials render beneath the image, and
an image that fails to load paints nothing over them, so the mark recovers without
hydrating.

<Composition themes caption="Image, initials, the anonymous mark, and an image that failed to load">
  <IdentitySpecimens group="states" />
</Composition>

| State | Shown | Backdrop |
| :--- | :--- | :--- |
| Image | The profile's picture, cropped to the circle | Covered by the image |
| Initials | Two characters of the nick | Derived from the nick |
| Anonymous | The `avatar` glyph | `--cn-surface-2` |

The mark renders the anonymous state without naming it. What a missing nick means —
a deleted profile, an anonymous one, a redacted one — and the localised word for it
are decided by the application, which prints the word in its own text.

The mark has three sizes. Small is one and a half lines, for a mark beside a line of
text; medium, the default, is two lines, for a mark that heads a region; large is
three lines, for the page that is about the profile itself.

## Telling profiles apart

The backdrop exists to separate the profiles that share a view. We derive it from
the nick, which keeps a profile's colour stable within a page and across the pages
of one release.

<Composition themes caption="Six nicks, six backdrops">
  <IdentitySpecimens group="distinct" />
</Composition>

We do not promise the colour beyond that. The derivation is an implementation
detail, and both ends of the range it mixes between are token roles, so a palette
revision recolours every avatar in the community. A consumer that needs a stable
colour for a profile stores one rather than reading it here.

Every colour the range can produce carries the initials at 4.5:1 and separates from
the page behind it at 3:1, in both schemes. The range inverts between them: dark
backdrops on the light page, light backdrops on the dark one.

## A list of marks

Where a view shows who is present rather than who did one thing — the readers
active in the community, the people who keep a site — the marks go in a list. The
class is `cn-avatar-list` on whichever element the composition calls for, usually a
`ul`. It arranges the marks it is given; how many of them there are is yours.

<Composition themes caption="Six linked marks in a list">
  <IdentitySpecimens group="list" />
</Composition>

The marks overlap, so a crowd reads as a crowd rather than as a row of separate
pictures. Overlapping costs them the separation that standing apart gave them, and
each mark takes it back from its own backdrop: inside a list the image draws within
the circle instead of filling it, leaving a rim of the colour its nick derived. The
list therefore needs to know nothing about the surface it sits on, and a mark
outside a list is unchanged.

A list does not size its marks — pass the size you want to each, and use one size
throughout a list.

<Composition themes caption="A list of small marks, and the same list at the default size">
  <IdentitySpecimens group="list-sizes" />
</Composition>

Past the width it is given, a list wraps. Every line begins at the same inline
position, so a wrapped list keeps a straight leading edge.

<Composition themes caption="A crowd wrapped in a narrow column">
  <IdentitySpecimens group="list-wrapped" />
</Composition>

### The marks a list does not show

A list may close with a count: `cn-avatar-list__overflow`, a plus and a numeral,
matching the marks in geometry and taking the anonymous mark's presentation because
it stands for no one profile. It carries no word — the design system serves three
languages and translates none of them, and a numeral needs no translation. Take the
matching size modifier when the marks are anything but medium.

<Composition themes caption="Four marks and a count, at both sizes">
  <IdentitySpecimens group="list-overflow" />
</Composition>

```mdx
<ul class="cn-avatar-list">
  {shown.map((profile) => (
    <li>
      <a href={`/profiles/${profile.key}`} aria-label={profile.nick}>
        <CnAvatar src={profile.avatarURL} nick={profile.nick} aria-hidden />
      </a>
    </li>
  ))}
  <li><span class="cn-avatar-list__overflow" aria-hidden="true">+{rest}</span></li>
</ul>
```

The count is decorative. A list whose total matters names it in the application's
own text, in the reader's language, the way the anonymous mark's meaning is named.

Marks with no nick derive no backdrop, so a run of them has nothing but each mark's
elevation between one circle and the next. It is the thinnest the overlap gets.

<Composition themes caption="The anonymous run: no nicks, no derived backdrops">

</Composition>

## Inside a link

Both marks are inert on their own: no pointer cursor, no hover response, no click
handler. Navigation belongs to the anchor that wraps a mark, not to the mark.

Inside an anchor, the circle loses the underline the anchor would otherwise draw
across it, takes the second elevation on hover, and takes a keyboard focus ring
that follows the circle rather than the anchor's rectangle. The textual mark keeps
its weight and colour and takes the link roles on hover and activation.

</Composition>

roles carry.

## Reference

The pictorial mark is the `CnAvatar` component, and [its book](/components/cn-avatar)
carries the props.

The textual mark takes no props. It is the class `.cn-nick` on whichever element the
composition calls for, and it presents the same on an anchor and on a span.

## Accessibility

The pictorial mark announces the nick and nothing else. We publish no wording around
it — no "avatar of", no "profile picture" — because the design system serves three
languages and translates none of them.

A mark inside a composition that already names the profile takes `aria-hidden`, so
that a linked avatar beside its nick announces the profile once. The anonymous mark
is always hidden, and a consumer that must name the anonymous state names it in its
own text.
