Content sits in a container. The container decides how wide the content may get,
how far it stands off the edges, and how much space separates it from the
container above. This page is inside one: the column you are reading is the
measure.

One container exists so far. Two-column, three-column and card layouts are the
rest of the family and are not built yet.

## Put one class on `<main>`

An application opts in by putting `cn-app-main` on its `<main>` element. Direct
`section` and `article` children are then containers.

```html
<main class="cn-app-main">
  <article>A container.</article>
  <section>Another, one --cn-line below it.</section>
</main>
```

There is no wrapper element and no component. A page that has not opted in is
untouched, which is how `apps/pelilauta` still lays out with Cyan while this
ships.

## Measure against the column, not the page

A container is `cn-content`, and it reports the column's width. A card here has
41.5rem to work with, not the 72rem the page might be.

```css
/* A card deciding how to lay out inside the column. */
@container cn-content (max-width: 30rem) { … }
```

This only works because the container element *is* the column. A container query
reports the container's own border box, so declaring one on a full-width wrapper
whose middle track holds the content would answer every question with the page's
width. v20 has that shape, and its queries are wrong for that reason.

## Two modes, and no threshold

Wide enough for the measure and a gap each side: the content is the measure,
centred, and the leftover width splits evenly. Narrower: the content takes what
is left after a `--cn-gap` gutter each side. Narrow this window to watch it.

There is no breakpoint between them. Both modes are one track:

```css
grid-template-columns: 1fr min(var(--cn-measure), 100% - 2 * var(--cn-gap)) 1fr;
```

The two terms are equal exactly where the measure and its gutters fit, so the
content cannot jump. A stated threshold could drift out of step with the measure;
this cannot, because there is nothing to keep in step.

## The measure

`--cn-measure` is `calc(var(--cn-grid) * 83)` — 41.5rem.

67 characters of the base paragraph is the readable line length, and 41.5rem is
what that measures to: Lato's `0` advance is 0.58em, so at the 17px base
paragraph 67 characters is 660.6px, or 82.58 grid steps, rounded up to 83.

It is written as a grid multiple rather than as `67ch` because `ch` resolves
against whichever font is rendering, and this site ships no font yet — the same
stylesheet would otherwise draw a different column in each application.

Being `rem`, it scales with the reader: a larger default text size gives a
proportionally wider column. See
[The reader sets the scale](/principles/spatial-system).

Re-measure when the base font or its size changes. Nothing else makes 83 wrong.

## Rhythm is `--cn-line`

Stacked containers are `--cn-line` apart. So are the blocks inside one — the gap
between these paragraphs is it.

That inside spacing is temporary in shape, not in existence. The
[preflight](/base/preflight) removes every element margin and hands the
replacement to whatever owns the layout, so the container supplies one uniform
step. The space before a heading and the space between two paragraphs are not
really the same decision, and the type ramp will separate them.

## Spanning the page

Bleed is a property of a whole container, not of something inside one. A
container marked `cn-grid-full` takes the full page width instead of the column.

```html
<main class="cn-app-main">
  <article>Prose, at the measure.</article>
  <section class="cn-grid-full">A wide table, spanning the page.</section>
</main>
```

A child cannot escape its container, and the reason is structural rather than a
missing feature: the container is exactly as wide as the column, so there is no
wider box inside it to reach for. Put what needs the page in its own container.

This page is a single container, so its own specimens sit at the measure.

## What this does not cover

The two-column and three-column layouts, and the card grid. v20 derives all three
from this same measure by golden-ratio steps, and they are the rest of this
family.

Cyan's `content-cards`, `content-listing`, `content-editor` and `content-sheet`
have no answer here yet. `apps/pelilauta` still uses all of them, and
`docs/MIGRATION.md` lists the screens involved.

Typography inside the container — sizes, leading, the space before a heading —
belongs to the type ramp.
