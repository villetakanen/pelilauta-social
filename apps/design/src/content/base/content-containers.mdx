## The host

`app-main` on a `<main>` makes it a host. It offers each direct child its full
content-box width, with no intermediate wrappers.

| Token | Applies to |
| :--- | :--- |
| `--cn-gap` | The page-edge inset. |
| `--cn-line` | Between stacked containers, and between the top-level blocks inside one. |

See [Units and grid](/tokens/units).

`content-prose` fills the width of whatever contains it — usually a `<main
class="app-main">`, which adds the page-edge inset — and centres its children at the
readable measure.

```html
<main class="app-main">
  <section>As wide as the host offered.</section>
  <article class="content-prose"><p>Centred at the measure.</p></article>
</main>
```

## The measure

<TokenTable source={containersSource} prefix="--cn-measure" />

It holds 67 characters of Lato at the reading size, and scales with the reader's
browser font settings. See [Spatial System](/principles/spatial-system).

The flow centres at the measure where the host offers more, and fills the host where it
offers less.

## Container query context

Each item in the flow establishes the `cn-content` container query context, so a
component asks about the column it sits in rather than the window.

```css
@container cn-content (max-width: 30rem) { … }
```

## Breaking out of the measure

Inside a prose container, a child marked `breakout` leaves the measure and takes the
width the container itself was offered. Use it for a table, a diagram, or a specimen
that a reading column would crop.

<div class="breakout surface">
  This block is a breakout. It is as wide as this page was offered, and it reports that
  width to the components inside it.
</div>
