We distinguish links from actions by outcome. A link navigates to a document,
resource, or location. An action triggers a command, submits data, or modifies state.

## Semantic distinction

HTML element selection defines control semantics, keyboard interaction, and accessibility
tree roles:

| Outcome | Element | Required attributes |
| :--- | :--- | :--- |
| Navigate to another document or URL | `<a href>` | `href` with explicit destination |
| Submit form values | `<button type="submit">` | None |
| Reset form values | `<button type="reset">` | Explicit `type="reset"` |
| Execute an in-page command | `<button type="button">` | Explicit `type="button"` |

A command remains an action even if execution terminates in a page redirect.

For example, a *Cancel* control returning to a previous URL is an `<a class="button" href="...">`,
while a *Cancel* control closing a modal dialog is a `<button type="button" class="button">`.
Both share identical button styling while maintaining correct native behavior.

## Button variants

Button styling is purely presentation and does not alter element semantics: `<button>` executes
commands, and `<a class="button">` navigates destinations. Both elements support the same
visual variants.

<DsComposition themes caption="The four button variants in Light and Dark">
  <ButtonSpecimens group="variants" />
</DsComposition>

| Variant | Purpose |
| :--- | :--- |
| Default | Standard priority actions and destinations. |
| `.text` | Low-prominence secondary actions where filled styling would compete with body content. |
| `.cta` | Primary call to action in a view (maximum one per region). |
| `.secondary` | The alternate chroma treatment, where it is explicitly required. Not the low-prominence variant. |

`.secondary` applies only when declared directly on the button element. Ancestor classes
do not cascade secondary color tokens to child buttons.

### Button anatomy and content

A button supports:
1. Text label.
2. Leading icon with label.
3. Icon-only control.
4. Inline `CnLoader` with or without label.

Buttons establish a scoped icon size, ensuring descendant `Icon` components automatically
render at the standard button size (small).

<DsComposition themes caption="Label, leading icon, icon-only, and loading state">
  <ButtonSpecimens group="compositions" />
</DsComposition>

An icon-only or loader-only button renders as a circular control. A command in flight uses a
disabled native `<button>` containing an inline `CnLoader`; the button retains the command's
accessible name while the loader indicates progress. Link buttons do not support loading states.

### Interaction states

- **Hover:** Elevates the control and overlays a subtle tint.
- **Active:** Deepens the tint while maintaining text contrast.
- **Keyboard focus:** Draws `--cn-color-focus-ring` around the control.
- **Disabled:** Native `<button>` elements render at `--cn-disabled-opacity`. This capability publishes no disabled presentation for a link: a destination is navigable, or the control is not rendered.

<DsComposition themes caption="Resting, disabled, and text link buttons">
  <ButtonSpecimens group="states" />
</DsComposition>

Transitions use `--cn-duration-ui` and `--cn-easing-ui`, disabling animation under
`prefers-reduced-motion: reduce`.

### Button geometry

Labelled buttons size to content by default and stretch to fill parent flex or grid tracks
when requested. When constrained, text labels truncate with an ellipsis while icons and
loaders maintain fixed square dimensions.

The corner radius equals half the visible block size, inline padding is `--cn-gap`, and
the space between an icon and its label is `--cn-grid` (0.5rem).

### The pointer target is larger than the pill

A button paints at `--cn-button-size`, and it answers a pointer over six grid units in
both directions. The two are not the same box: the target is centred on the pill and
reaches past it, further on an icon-only control, which paints a circle narrower than the
target in both axes.

Nothing is painted to show it. The target is an empty box on the control, so a pointer
landing just outside the pill still lands on the button — which is what a reader touching
a phone, or aiming with a trackpad, actually needs.

The target fits inside the row a button already occupies, so it changes no layout: the
pill's own block spacing is wider than the amount the target reaches past it.

A component that builds its own control from these rules — a chip, a chrome action, a
reaction button — sets its own target and says so in its own book.

## Floating action buttons (FAB)

A floating action button (FAB) exposes the primary contextual action for a view. Use
`<button class="fab">` for commands and `<a class="fab">` for navigation.

<DsComposition themes caption="The three FAB variants in Light and Dark">
  <FabSpecimens group="variants" />
</DsComposition>

| Variant | Purpose |
| :--- | :--- |
| Default | Standard contextual action. |
| `.cta` | High-emphasis primary action. |
| `.secondary` | Supporting action beside a primary FAB. |

### FAB sizes and content

FABs support an icon alone or an icon with trailing label. Two sizes are available:
- **Standard (7 grid units / 56px):** Primary view action.
- **Small (`.small` / 38px):** Collapses to `--cn-button-size`.

Icon-only FABs are square. Labelled FABs expand inline; neither variant stretches to fill
flex tracks.

<DsComposition themes caption="Standard and small FAB sizes">
  <FabSpecimens group="sizes" />
</DsComposition>

<DsComposition themes caption="Icon-only, labelled, and in-flight FAB">

Icon-only FABs derive their accessible name from the button `aria-label`, never from the icon.
In-flight commands use a disabled native button containing an inline `CnLoader`.

### FAB interaction states

Hover lifts the FAB above its resting elevation, active settles between elevations, and
keyboard focus applies `--cn-color-focus-ring`. Only native button FABs support the disabled state.

</DsComposition>

### FAB tray container

Use `<nav class="fab-tray">` to pin FABs to the lower inline-end corner of the composition
that owns it, which is its containing block. The tray spans that composition's inline size
and aligns its children to the inline end. It stacks at `--cn-z-fab` and clears block-end
navigation through `--cn-block-end-chrome`.
