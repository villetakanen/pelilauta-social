# Next Task

Choose the problem worth addressing next, then size the deliverable.

Use the operator's current scope when one is established.
Otherwise, survey open issues and epics across the backlog before choosing.
Read the full issues for plausible candidates; list order and recent discussion
do not establish priority.

Check each shortlisted candidate against current code, specs, and project state.
Establish the remaining unmet need; treat issue descriptions as claims to verify.
Flag completed, superseded, or obsolete candidates without changing their issues.
Assess older release and migration assumptions against the live application.

Compare candidates by consequence, urgency, reach, dependencies, effort, and
uncertainty. Follow explicit operator priorities.
Use lower effort to distinguish comparable benefits; identify when a small task
would defer a more consequential need.

For the selected problem, find the smallest increment with a usable outcome.
Include the adoption, documentation, and verification needed for that outcome.
Follow [AGENTS.md](../../../AGENTS.md) for spec readiness and approval boundaries.
If a decision blocks valuable work, propose the work needed to settle it.

Present one proposal with its evidence, scope, and completion check.
Explain why it precedes the strongest alternative and identify material uncertainty.
Propose only; change issues, specs, or code when the operator requests that work.
